## Why this matters

`apps/web/package.json` declares 7 packages that nothing in the repo imports:
`mobx`, `mobx-react-lite`, `@stitches/react`, `react-intl`, `react-day-picker`,
`react-error-boundary`, `react-hotkeys-hook`. They inflate install time and the
lockfile, widen the supply-chain surface, and mislead readers about the stack
(state is Zustand, styling is Tailwind 4 — not MobX or Stitches). Removal is
purely subtractive.

## Current state

- `apps/web/package.json` — `dependencies` block lists (among real deps):
  `@stitches/react: 1.2.8`, `mobx: 6.15.0`, `mobx-react-lite: 4.1.1`,
  `react-day-picker: 9.14.0`, `react-error-boundary: 3.1.4`,
  `react-hotkeys-hook: 3.4.7`, `react-intl: 6.1.1`.
- Verified at planning time: this grep returns **zero** matches across all
  workspaces:

```
grep -rn "from ['\"]mobx\|from ['\"]@stitches\|from ['\"]react-intl\|from ['\"]react-day-picker\|from ['\"]react-error-boundary\|from ['\"]react-hotkeys-hook" apps packages --include='*.ts' --include='*.tsx' --include='*.jsx'
```

- The repo enforces frozen installs (`bun install --frozen-lockfile` per
  README), so the lockfile must be regenerated intentionally with a plain
  `bun install` after editing the manifest.
