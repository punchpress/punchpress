# Verification: documents and assets

Use disposable content and files. Run each section from its stated setup with default preferences and source baseline `d4e6d4a`. Browser means the default web editor; desktop means a packaged build except the explicit development comparison. Keyboard/mouse rows use normal UI input. Native dialogs, permission changes, real touch/stylus, controlled slow responses, and updates need the corresponding environment. Never perform destructive file experiments on user artwork. All results are `not run`: source tests were read, not substituted for these UI checks.

Question rows ask for an observation; resolve the description before recording a passed contract. Each modifier and interrupt has separate before/extended rows because command/dialog phases are distinct. For a pending operation, use a slow disposable input or controlled response delay; if that state cannot be held honestly, record blocked with the reason.
